# SENTINEL — Surveillance Intelligence Console

A map-based public-space monitoring console in a tactical SOC style, with a
**real in-browser AI vision engine** running over public CCTV points.

Inspired by the "intelligence console" aesthetic from the reference clip:
dark HUD, satellite map, live event feed, timeline. Built as a front-end you
can run and extend.

![stack: HTML + Leaflet + TensorFlow.js](https://img.shields.io/badge/stack-Leaflet%20%2B%20TF.js-37e39b)

## What it does

- **National satellite map** (Esri World Imagery) with **~1,000 real public
  toll-road CCTV nodes** plotted from the BPJT registry (see Data source),
  across Jakarta, Bandung, Semarang, Surabaya, Medan, Makassar, Sumatra and
  more. A **city selector** flies to and filters each place; a text filter
  searches name / road / operator.
- **BTS / cell-site layer** — a toggleable layer of **representative** cell
  towers (operator, band, 4G/5G, coverage radius). See the note under Data
  source: these are illustrative infrastructure points, not real coordinates
  and not tied to any device.
- **Control layers**: CCTV nodes, BTS cell sites, street labels, density
  heatmap, coverage radius.
- **AI Vision engine** — click any camera → **COCO-SSD** object detection
  (TensorFlow.js, `mobilenet_v2` base) runs in the browser on:
  - **Live HLS** — the camera's real public stream, played via `hls.js` and
    analyzed frame-by-frame (the default when a node has a stream). Eight
    verified-live cameras are pinned as presets; paste any `.m3u8` URL to
    analyze your own.
  - **Simulated feed** — a synthetic street scene, works with no network/camera.
  - **Webcam** — real detection on your own camera.
  - **Video File** — real detection on any local clip you load.
- **Network-wide analytics**: vehicle/people rates, per-class bars, rolling
  activity sparkline, and a live anonymous **event feed** (congestion,
  density, node health).

Detections are generic COCO traffic classes (`car`, `truck`, `bus`,
`motorcycle`, `bicycle`, `person`). Large boxy vehicles that COCO mislabels as
`train` from an overhead toll angle are folded back into `truck`.

## Data source

Camera points and HLS stream URLs come from **BPJT** (Badan Pengatur Jalan Tol,
Kementerian PU) — the toll-road regulator's public camera registry at
<https://bpjt.pu.go.id/cctv/>, which publishes operator, road, KM marker,
coordinates and an HLS URL per camera for public traffic viewing.

`js/cctv-data.js` is **auto-generated** — don't hand-edit it. Stream IDs rotate,
so regenerate when cameras stop resolving:

```bash
python3 tools/update_cctv.py                 # all Indonesian toll cameras
python3 tools/update_cctv.py --bbox -6.4,106.68,-6.08,107.02   # one area only
```

Each camera is tagged with its city from a metro bounding-box table in the tool.
The featured presets in `FEATURED_URLS` (Jakarta, Surabaya, Sumatra) were each
verified live, H.264, and CORS-open down to the segment. Jasa Marga's `jmlive`
host (which serves Bandung, Semarang and others) is frequently down — those
cameras still plot as markers but their live playback falls back to the
simulated feed until the host recovers.

**BTS layer** (`js/bts-data.js`) is **representative** data generated by
`tools/gen_bts.py` — plausible cell-site positions clustered around the CCTV
cities and corridors, with operators and bands. It is *not* a real tower
registry. To use real coordinates, export towers from
[OpenCelliD](https://opencellid.org) and emit the same record shape
(`{id, operator, band, g, city, lat, lng, radius}`):

```bash
python3 tools/gen_bts.py            # regenerate the representative layer
```

## Deliberate scope / ethics

This console does **generic, anonymous** analytics only — object classes like
`person`, `car`, `bus`, `truck`, `motorcycle`, `bicycle`, and aggregate counts.

It intentionally does **not** implement:
- facial recognition or any biometric identification of individuals,
- profiling or tracking of named/specific people,
- aggregation of anyone's personal data (phone, address, financial, travel,
  location history),
- any link between the BTS layer and device/phone location — the cell sites are
  static map context only, never a means to locate or triangulate anyone.

Those features turn a monitoring tool into a targeted-surveillance /
stalkerware system, so they are out of scope. Keep deployments to public
spaces you are authorized to monitor, and follow local privacy law.

## Run it

From the repo root:

```bash
python3 -m http.server 5173
```

Then open <http://localhost:5173>. (A browser is required — the AI model and
map tiles load from CDNs, so you need an internet connection on first load.)

## Hosting

It's plain static files with no build step, so any static host works — this
repo is set up for **GitHub Pages** (`.nojekyll` makes Pages serve files as-is).
All camera streams are `https://`, so nothing is blocked as mixed content.

Note: the claude.ai **Artifact** viewer blocks every cross-origin image and
`fetch`, so inside an Artifact the map tiles, live HLS streams and model weights
don't load. Live features need a normal static host like this one.

## The CORS constraint (important)

`hls.js` fetches each segment over `fetch`/XHR, so a stream only works in the
browser if its server sends `Access-Control-Allow-Origin`. If it doesn't, the
video may still play but the canvas becomes **tainted** and
`tf.browser.fromPixels()` throws — the engine detects this, keeps the picture
up, and shows *"detection blocked (CORS-restricted feed)"* instead of failing.

The BPJT toll cameras used here send `Access-Control-Allow-Origin: *`, so both
playback and detection work. For a feed that can't (many city CCTV portals), run
a small reverse proxy / `ffmpeg` re-stream that adds the CORS header, and point
the console at that instead.

## Architecture

| File | Role |
|------|------|
| `index.html`         | Layout, HUD shell, camera modal, HLS controls |
| `css/styles.css`     | Tactical SOC theme |
| `js/cctv-data.js`    | **Auto-generated** CCTV node dataset (BPJT), city-tagged |
| `js/bts-data.js`     | **Auto-generated** representative BTS cell-site layer |
| `js/vision.js`       | `VisionEngine` — COCO-SSD + `hls.js` + webcam/file/sim |
| `js/app.js`          | Map, markers, layers, city selector, analytics, modal |
| `tools/update_cctv.py` | Regenerate `cctv-data.js` from the BPJT registry |
| `tools/gen_bts.py`     | Regenerate the representative `bts-data.js` layer |

## Scaling up (server-side)

For many simultaneous real feeds, move inference off the browser:
decode streams on a server/edge box and run a detector (YOLOv8 / RT-DETR via
ONNX Runtime or a Triton server), then push detections to this UI over
WebSocket. The front-end stays the same; only the stats source changes.
